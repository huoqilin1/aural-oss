# 数君招聘候选人面试冻结合同

版本：`recruit-interview-v12-fast-start-human-paced`。适用于标题匹配 `数君招聘 · ...` 的面试。

本合同任何条目的删除、放宽、替换或重新解释，都必须获得王总对该条目的单独手动批准，
并同步更新 HR、Aural、官网回归测试。一次笼统批准不能修改多项。

## 候选人入口与快速开始

### 2026-09-07 后续批准：测试期间豆包主力、DeepSeek 深度思考

王总明确恢复原方案，测试期间主力豆包、深度思考 DeepSeek。
`RECRUIT_TEST_MODEL_ROUTING=1` 优先于旧单模型标志。实时对话依次豆包、
DeepSeek、Kimi、GLM；后台出题与报告依次 DeepSeek v4 Pro、豆包、Kimi、GLM。
每模型一次、失败留证与持久停止、人工恢复规则不变。GLM 仅标准 API。
测试后不自动切换，最终配置必须重新通过受影响验收。其余冻结条款不变。

实时豆包关闭深度推理，后台 DeepSeek 显式启用深度思考。会话 API 向已授权
HR 提供该会话的最新语音连接状态；原始会话标识不写入连接遥测文件。
HR 不能仅因模型处理期间没有新落库消息而将在线会话标为中断。

### 2026-09-07 先前批准：仅 GLM-5.3（已被上述后续批准替代）

王总明确要求“不准用 KIMI 和 deepseek，只能用 GLM5.3”。启用
`RECRUIT_GLM_ONLY=1` 后，招聘文本生成、面试对话、报告与评分仅调用
`zhipu / glm-5.3`，覆盖旧配置和已有任务路由，不执行其他文本模型回退。
失败必须保留证据与停止状态，不自动重开；原 ASR/TTS 音频服务保持使用。
HR 与 Aural 同步启用并重新验收。其余冻结条款不变。
生产使用标准 API 权益；Coding Plan 订阅额度不能直接当作自建网站 API 余额。

固定流程：`阅读须知 -> 一次“开始面试” -> 自动连接摄像头和麦克风 -> AI 自然开场 -> Q1`。
摄像头保持启用；不得增加摄像头测试、麦克风/语音测试、设备检测页、试听页、第二个站内
开始按钮或授权按钮。浏览器自身首次权限弹窗不得绕过。

Q1 计分自我介绍、确定性的双锚定 Q2 和有效邀请就绪后立即开放，不等待 Q3-Q8。Q2 必须
同时引用隐私安全的简历经历锚点和具体岗位职责锚点。候选人阅读须知、连接设备和回答 Q1/Q2
时后台动态补齐 Q3-Q8；未就绪时不得用通用题或虚构经历凑数。点击开始到 AI 开场目标不超过
10 秒；动态扩题不得替换已经开始或回答的问题。

## 题目、追问和节奏

- 必须完成八道固定计分题：计分自我介绍、核心经历所有权、核心技能证据、结果数据验真、
  岗位工作样例、复杂问题解决、AI 与学习验证、协作动机与稳定性。
- Q2-Q8 每道同时锚定具体简历事实和岗位要求；无对应经历时基于已有经历问迁移依据和差距。
- 正常 0-2 次就地核验，八题后可有 0-1 次最终动态核验，全场最多 3 次且不要求用满。
  每次只补本人角色、机制、选择依据、数据口径、失败验证或时间线中的一个缺口。
- Q1 不追问；Q2-Q7 每题最多一次且全场合计最多两次；Q8 最多一次可选核验。主线路、备用
  线路和重连后均由服务端执行同一预算，不能只依赖模型提示词。
- 正常每道约 2 分 30 秒至 3 分钟，整场中心目标约 30 分钟，但不设置候选人活跃回答时的
  业务硬截止。回答相关时允许说完；偏题时等自然停顿后礼貌聚焦；仍须完成八道题。
- 可清理断线或长时间无活动会话，但不得把持续正常回答的招聘会话按时间强制完成。
- AI 不机械报题号、不重复空泛表扬、不抢话；重连后从原问题继续且不重复计分。

## 证据与验收

AI 只能报告证据充分、证据不足、前后矛盾或待核实，不得直接认定撒谎，也不得根据表情、
口音、停顿和表达风格判断真实性。报告分别呈现岗位匹配 35、已证明能力 30、证据可信度 25、
动机与稳定性 10，并为每一维绑定 Q1-Q8 题号和回答证据。缺项或缺题号时必须失败关闭、重试
或转人工复核，禁止进入排序。

本地和生产验收必须证明：申请到 Q1+Q2+邀请 P95≤15 秒且单次≤30 秒，Q1 计分、Q2-Q8
双锚定、八题完成、通用替代为 0、追问不超过 3、`next_question_not_ready` 为 0、无 32 分钟
强停、无跳题/重复题/内部异常；若下一题异常则必须明确告知并自动重试，绝不能发等待填充题。
一份获授权的现有真实简历（原件或已有脱敏副本均可）通过后扩至 5 份，
必要时扩至 10 份。并发只按 `5 -> 10 -> 20`，且必须同时证明题目准备和对应数量的活动语音
会话/WebSocket，20 路通过即完成，准备能力不得冒充真人语音能力。

## 分层发布验收与结论表述

验收必须按不同证据层完成，重复三遍源码/正则检查不能替代行为和生产证据：

1. 逐条规则与代码审计，并建立要求、实现、测试和生产证据的对照关系。
2. 可执行本地验收同时覆盖正常流程及静默、无回答推进、提前完成、抢话/文字竞态、断线
   重连、主备中转、动态扩题、保存同步失败、八题完整性、追问预算和自动音视频入口。
3. 从已测试的明确提交完成干净生产构建，并记录 Git SHA 和制品 SHA-256。
4. 部署后核对线上版本、服务、API、浏览器入口与获批 SHA。
5. 单独获得生产写入授权后，用获授权的现有真实简历原件或已有脱敏副本从官网投递，完成模拟语音面试；随后
   在 HR 与 Aural 对齐八题回答、追问数、完成状态、四维评分和证据引用。
6. 按需完成 5 份（必要时 10 份）质量样本及 5/10/20 路真人语音并发。

第 3 层以前只能报告“本地验收通过”；第 4 层通过只能报告“已部署，生产真人验收未完成”；
第 5 层通过只能报告“单样本生产验收通过”。只有本次范围内所有门槛全部通过，才可报告
“全部完成”。任何代码、配置、制品或部署 SHA 变化都会使受影响的下游验收失效；任何生产
失败都必须重新打开任务，修复后重跑受影响层级，禁止沿用旧结果或称为完成后的优化。

## 模拟简历规则（2026-09-06 王总单项批准）

模拟面试不强制脱敏。获授权原件和已有脱敏副本均可，不得因为未脱敏而阻塞测试、
重复索要脱敏批准或制作副本。生产批次、岗位和样本数量授权仍保留；日志、截图与报告
不得公开简历正文或个人联系方式。模拟回答和结果只代表测试，不代表简历本人陈述或能力，
不得据此发送本人通知或作正式录用评价。
