# 音频历史失败继续定位

## 已确认并修正的检查器缺陷

旧检查器只用固定第 48000 个样本开始的 1024 样本窗口定位。其余检查允许围绕一个固定偏移最多 ±256 样本的时钟对齐，并要求相关性大于 0.97、未匹配总量不超过 1024、连续缺口不超过 512。

`node scripts/diagnose-audio-anchor.mjs` 对比基础提交 `b478728f379c75c0f85f89d95d18dbee0c15c71e` 与修正版。相同的 160 样本调整发生在 20000 时旧检查通过，发生在 48000 / 48480 / 48800 时旧检查失败，相关性分别约为 0.857 / 0.549 / 0.821。这证明检查器的结论受位置影响。**不证明缺少原始 PCM 的首次 Q5 失败一定由此造成。**

修正为在三个定位窗口中找到一个完整窗口，然后仍围绕同一个固定偏移检查全部短窗口；没有逐段任意重新对齐。上述阈值不变。新增不同位置的 160 样本调整，以及位于定位窗口的 4096 样本传输帧缺失/重复反例；5 项测试通过，原有静音和变速反例继续拒绝。

- 对比证据：`output/audio-anchor-counterexample.json`，8 个确定性案例，退出 0。
- 回归：`node --test tests/voice-audio-content.test.mjs`，5/5，`output/audio-anchor-regression-20260914.log`。
- 检查器 SHA256：`a6caad366311bad24e5ef42bfb6ec758b28df4d8bdc735b0ccf9704889189c03`。

## 采集输入到发送 PCM 的新增观测

`AURAL_AUDIO_CAPTURE_TAP=1` 在实际 AudioWorkletNode 的消息端口增加只读监听，复制输入 Float32 样本，保留所有实际发送包。重放实际转换器后按顺序查找非静音包的逐字节对应。此检查用于定位输入与发出数据的差异；它不是独立算法正确性证明，也不能单独证明无漏包，原有全段内容检查仍必须通过。

- 修正检查器前的实际八题：`output/audio-input-diagnostic-20260914-085008/`，退出 0，8/8 内容及摄像头轨检查通过。
- 两次采集上下文均为 48kHz，分别记录 688 / 416 个输入块；260 个非静音发送包全部逐字节匹配，无不匹配包。
- 保存了原始合成输入 `.input.f32`、每题实际 `.pcm`、期望 `.expected.f32`、时钟与包到达 `.timing.json`。不含真人音频。
- 修正检查器后的完整复测已退出 0，会话 `51682` 已结束；目录 `output/audio-anchor-fixed-20260914-085304/`，8/8 内容及摄像头轨检查通过。两次采集上下文记录 683 / 417 个输入块，259 个非静音发送包全部逐字节对应，无不匹配包。浏览器和本轮模块测试服务已由 finally 关闭。

Chromium 的 [WebAudio MediaStream sink 实现](https://chromium.googlesource.com/chromium/src/+/d27dad4649f1c35e08af6c9ad343d8037c2645b7/third_party/blink/renderer/modules/mediastream/webaudio_media_stream_audio_sink.cc) 包含重采样、缓冲及 underrun 时补零行为。这支持继续区分原生音频图与产品转换路径的诊断方向；它不是本机首次故障的因果证明。

## 仍需保留的边界

本轮没有改产品音频代码，没有关闭摄像头，没有放宽原有数值阈值。修好测试检查器不等于修好了历史现场问题；旧失败记录保留。完整 Next 原命令本轮仍在进程创建前被自动审批拒绝，只返回 `blocked by policy`，无具体原因，未绕过。完整页面/真实模型/生产验收仍未通过，无推送或部署。
