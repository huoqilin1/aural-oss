# 招聘面试保存与结束一致性变更说明

本地执行记录，2026-09-05。未合并、未部署、未对生产执行迁移。

## 保持的业务规则

原 AI 独立评分、岗位权重、AI 淘汰线、一面六维和二面规则完全保持。辅助报告不替代原评分。
本次只补保存确认、结束时的记录版本和异常提示；不得据此把工程测试当作招聘判断质量或真人验收。

## 接受回答的边界

迁移 `supabase/migrations/007_recruit_voice_completion_guard.sql` 为 sessions 添加 `voiceRevision` 和
`completedVoiceRevision`。只对标题匹配 `数君招聘 · ...` 的场次启用新约束。

- 每次实际插入、修改、删除材料，都与结束操作竞争同一场次的数据库行锁，更新记录版本。
- 重复发送同一个已保存的消息 ID 不增加版本；应用仍逐字段验证，不能用旧 ID 换新内容。
- 有题目编号的新增或改写记录，必须对应当前面试的题目；其他面试的题目、不存在的题目和跨场移动证据均拒绝，不增加成功保存版本。
- 结束时携带读取到的版本；数据库还要验证正式八题均有非空 USER 回答。发生更新则拒绝旧结束请求，允许重试。
- 结束先成功、其后才提交的新材料会明确拒绝。浏览器不能删除这次未获确认的文本，必须提示该补充尚未纳入报告并联系招聘负责人核实。这里没有自动补录、自动重新评分或自动通知政策。
- 结束后禁止单独改写或删除证据。原有整场删除的外键级联清理仍可执行，受原权限及留存政策约束。
- 新报告必须基于已确认的完成版本；写回时再次比较版本和状态。读取失败、写入失败或版本已变均不能记录为生成成功。
- 页面重复点击结束时共用同一次尚未结束的保存操作。界面等待超时不取消仍在执行的请求，也不启动第二个结束请求。
- 白板、代码保存要收到实际保存记录。失败时不能显示已保存，不能继续依赖这些材料推进或结束。

## 兼容与发布条件

1. 新列为增量添加，旧场次内容不重写；历史 `completedVoiceRevision` 保留空值，不编造旧版本。历史报告仍按原记录读取；需要重新生成时应按历史恢复方案单独核实和授权。
2. 非招聘面试不增加八题或封闭限制。所有受影响结束写入入口都已传入版本，并检查数据库拒绝。
3. 迁移和应用是一组发布依赖。旧应用没有发送版本，不能单独启用新触发器后继续把旧应用当正常服务。
4. 生产上线前须核实无活跃面试的合适窗口，或先实现并验证兼容发布机制；不能强制结束正在回答的候选人来制造窗口。本地竞争测试不代替该发布条件。
5. 从获准的远程 main 精确提交生成制品；确认备份、应用版本、数据库迁移和回退步骤，再按仓库发布规则执行。未获准前不运行生产迁移。
6. 若需回退，先按发布流程停止接入不兼容版本的流量，在获准窗口恢复对应应用与触发器组合。保留新增列及已写入版本数据，不删除候选人材料来回退。移除新触发器会失去这层保护，所有相关下游验收失效，不能继续沿用本轮通过结论。

## 本地证据与尚未证明的内容

`tests/completion-guard-postgres.test.mjs` 在唯一命名的本地隔离 schema 中执行实际迁移两次，验证：
八题完成、缺版本、旧版本、七题阻断、写入先到、完成先到、完成后的修改删除、整场级联删除、跨场改归属、非招聘兼容。
`tests/session-storage-errors.test.ts` 调用真实 tRPC 路由验证失败不能返回成功。
`tests/functional.test.ts` 包含真实浏览器中保存超时后重试不重复结束的用例，媒体及远端服务使用模拟。

这些测试不证明主备识别服务自身的修订先后正确、不证明浏览器关闭后未同步内容可恢复、不证明真实音视频文件完整、
不证明 HR 已同步最新版本，也不证明真人面试质量或 5/10/20 路真实语音容量。相应项目仍按总验收标准继续。
