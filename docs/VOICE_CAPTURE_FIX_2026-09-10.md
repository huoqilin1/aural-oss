# 面试录音变短：修复与验收说明

线上编号 2218 的单场模拟测试在第一题失败，18.0745 秒测试回答只发出 14.592 秒录音。按批准范围停止，没有重开，尚未验收八题、公司答疑和最终报告。

## 这次改什么

播放使用设备原本的速度。录音使用独立的处理通道，不接扬声器，避免播放设备在静音或恢复时切换时钟、带走一段录音。录音连续转换为识别服务要求的 16k 格式，保留跨回调的零头，每次仍发送 4096 个采样点，保持原有识别、音量和抢话判断节奏。暂停录音只关闭采集通道，不影响面试官播放；再次开启时重新建立干净的采集通道。

## 怎么判断修好

- 用真实网页录音代码、完整录制代码和摄像头，播放开场后连续发送八段带固定标记的声音，第五段前暂停再恢复录音。
- 同时检查发送时长和声音内容。比对固定一个位置，只允许有限的小幅媒体校时；累计无法匹配不超过 64 毫秒，单处不超过 32 毫秒。故意丢掉或重复一整个传输帧、发送静音、让声音变慢，都必须判失败。这是本地音频传输检查，不是候选人回答质量评分。
- 转换测试覆盖 8k、16k、24k、44.1k、48k 输入、跨回调零头、连续一分钟计数，以及停止后重新开始。
- 继续执行全部已有自动检查、功能检查和正式构建。
- 发布后重新核对版本、服务和页面；线上面试需要重新批准明确场数，不能复用 2218 的失败记录作为通过证明。

运行命令：`npm run test:audio`（Windows 会打开本地浏览器，不调用生产接口）；`npm run test:web`；`npm run test:functional:components`。正式构建另跑打包服务的功能检查。

本地音频检查只证明在录制运行时发送给识别服务的音频符合上述边界，不证明成品录音文件、八题报告、多份简历质量或并发已经验收通过。
