# 招聘数据权限修复：独立批次 008

本批从 origin/main 16bd18e9c6000cc7b8425f03a1a3f1a5ed6707f2 建立，只包含数据库权限迁移、测试及说明，不混入正在修改的语音和评分代码。没有改变 AI 分、权重、淘汰线、岗位分类或任何候选人的评分。

## 解决的问题

线上只读权限核查发现：匿名角色可以读取带邀请的候选人记录；普通登录角色的媒体访问策略只判断文件桶；两种创建面试的特权函数允许客户端直接执行。本次没有读取候选人内容，也没有证据证明已经有人利用这些权限。

迁移收紧匿名和普通登录角色对招聘面试、题目、场次、候选人和消息的直接数据库访问，禁止直接调用两种创建面试函数。服务端 service_role 保留访问。三个共享私有文件桶（录音、截图、白板）改为由服务器提供签名访问；其他文件桶不受本批影响。共享桶中的普通练习文件也受此限制。

## 范围与限制

- 应用当前通过 service_role 访问数据库并调用创建函数，因此此迁移可作为独立缓解措施；它没有替服务端接口增加用户身份校验。接口和主备语音连接的授权补丁必须另行发布验收。
- 不删除数据、不重置邀请、不重新评分、不发送通知、不改变已有签名链接的有效期。过去发出的有效签名链接不会因本迁移自动失效。
- 招聘识别沿用当前标题规则“数君招聘 · …”。其他命名的招聘数据是否存在尚需另项核查。
- 007 尚未进入基线。本批仅把它放入 tests/fixtures 作为兼容性测试材料，不发布或执行 007。不可运行整个工作区的全部未发布迁移。
